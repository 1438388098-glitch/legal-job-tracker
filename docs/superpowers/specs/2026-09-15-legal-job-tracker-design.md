# 法学招聘信息收集与管理系统 · 设计文档

日期：2026-09-15
状态：设计已获用户逐段确认

## 1. 背景与目标

面向法学求职者的个人单机工具（PC 端使用）。痛点：招聘信息散落在微信公众号文章、招聘网站、官方公告页、学校渠道/群聊转发等多个渠道，同一信息多处重复，链接刷屏即失效，人工跟踪投递进度几乎不可能。

目标：建一个**运行在用户自己电脑上的本地系统**，自动收集珠三角 + 韶关地区的法学相关招聘信息，统一去重入库，提供本地网页完成筛选浏览、投递进度跟踪、截止时间提醒与过期归档。

## 2. 需求清单（已确认）

- **目标岗位类型**（四类全覆盖）：律师事务所、体制内/公职类（法院检察院聘用制、事业单位、国企、公务员）、企业法务/合规、实习岗位。
- **地域范围**：广东珠三角九市（广州、深圳、珠海、佛山、惠州、东莞、中山、江门、肇庆）+ 韶关。
- **信息来源**：微信公众号文章、招聘网站/APP、官方公告页、学校渠道与群聊转发。
- **采集方式**：系统自动采集为主；微信公众号走半自动"粘贴箱"兜底。
- **管理动作**：截止时间提醒、投递进度跟踪、搜索筛选、去重归档。
- **交互方式**：本地网页为主。

## 3. 总体架构

```
┌─────────── 采集层（定时调度 + 手动触发）───────────┐
│  官方公告适配器（人社局/法院/律协/学校就业网…）      │
│  公众号粘贴箱接入口（用户粘链接 → 抓正文提字段）     │
└──────────────────────┬────────────────────────────┘
                       ▼
┌─────────── 数据层：SQLite 单文件（job.db）─────────┐
│  jobs 岗位表 + FTS5 全文索引                        │
│  applications 投递记录    sources 信息源健康表      │
│  collect_logs 采集日志    正文快照文件目录           │
└──────────────────────┬────────────────────────────┘
                       ▼
┌─────────── 展示层：FastAPI + Jinja2/HTMX ─────────┐
│  岗位列表  岗位详情  我的投递看板  源健康页          │
└───────────────────────────────────────────────────┘
```

技术选型：Python 3.12+、FastAPI、SQLite（FTS5 全文索引）、httpx + selectolax（抓取解析）、APScheduler（进程内定时）、Jinja2 + HTMX（服务端渲染 + 局部刷新，零前端构建步骤）。单机自用，不引入数据库服务与前端工具链。

## 4. 数据模型

### jobs 岗位表（核心字段）

| 字段组 | 字段 | 说明 |
|---|---|---|
| 基本 | title, org, job_type | 岗位类型枚举：律所 / 体制内 / 法务 / 实习 |
| 地域 | city | 珠三角九市 + 韶关，支持多值（如"广州/深圳"） |
| 时间 | publish_date, deadline, source_published_at | deadline 为空表示公告未注明，提醒规则跳过 |
| 原文 | source_channel, url, snapshot_path | 快照存正文 HTML/文本到本地文件 |
| 法学特有 | legal_cert_required, notes | 是否要求法考A证、编制/应届等备注 |
| 管理 | status, dedup_fingerprint | 状态枚举：pending（粘贴箱待确认）/ new / read / archived |

### applications 投递记录表

- job_id（外键）、status（待投 → 已投 → 笔试 → 面试 → Offer / 拒）、timeline（事件时间线）、notes（自由备注）。

### sources 信息源表 + collect_logs 采集日志表

- sources：名称、类型、URL、适配器标识、启用开关、上次成功时间、连续失败计数。
- collect_logs：每次采集的时间、源、新增条数、去重条数、错误信息。

### 去重指纹

- 指纹 A：URL 归一化（剥除 utm_* 等跟踪参数、统一 http/https 与末尾斜杠）后哈希。
- 指纹 B：org + title 归一化后的相似度（difflib SequenceMatcher 比值 ≥ 0.85 判定），命中则合并为同一条记录、追加来源链接，不重复建条目。

## 5. 采集子系统

### 5.1 第一批信息源（MVP）

| 源 | 覆盖内容 | 采集方式 |
|---|---|---|
| 韶关市人社局、广东省人社厅 | 事业单位/国企招聘公告 | 定时抓列表页 + 详情页 |
| 广东法院网及广深法院官网 | 聘用制书记员、审判辅助岗 | 同上 |
| 广州/深圳律师协会官网 | 律所招聘信息 | 同上 |
| 用户学校就业信息网（学校名待用户提供） | 校招、实习、宣讲会 | 同上 |
| 公众号粘贴箱 | 微信公众号文章 | 半自动：用户粘链接 |

明确排除：BOSS直聘/智联/猎聘等强反爬招聘平台不进第一版；后续如需要，通过粘贴箱手工补充。

### 5.2 适配器接口与流水线

采集器采用**配置驱动的通用静态列表引擎 + 少量特殊适配器**：官方静态列表页（占绝大多数）只需在 sources 表新增一条配置（列表页 URL、条目/标题/日期选择器、默认城市与岗位类型），由同一引擎执行流水线；仅 JSON 接口源（中南财就业中心）与公众号粘贴箱走专属适配器。

```
fetch 列表页 → 解析出条目 → fetch 详情页 → 字段标准化
→ 去重（指纹A/B）→ 正文快照落盘 → 入库 → 写日志
```

新增信息源 = 新增一条源配置，框架代码不变。适配器单元测试使用录制好的真实 HTML fixture（`scripts/save_fixture.py` 录制）。**信息源全量清单与验证结果见 `docs/source-registry.md`**（T1 静态规整 13 个 / T2 可抓有毛刺 23 个 / T3 需渲染暂缓 12 个 / P 粘贴箱兜底 13 个）。

### 5.3 公众号粘贴箱

- 网页输入框接受 `mp.weixin.qq.com` 链接 → 系统抓取正文 → 规则提取字段（岗位名、单位、截止时间、城市、类型）→ 弹出**确认页**预填所有字段 → 用户核对修改后入库。
- 设计理由：公众号反爬严格且标题党多，全自动不可靠，一秒人工确认换取数据干净。

### 5.4 健壮性

- 单源失败不影响其他源；网络错误指数退避重试（最多 3 次）；连续失败在源健康页标红。
- 正文快照本地存档，原文删除/过期不受影响。
- 全部采集动作写日志，可追溯"某天为什么没收到新信息"。

## 6. 网页功能

### 6.1 岗位列表（主页）

- 默认视图：未归档 + 按截止时间升序（无截止日期的排其后，按发布时间降序）。
- 左栏筛选器：岗位类型 / 城市 / 状态 / 关键词全文搜索（FTS5）。
- 截止时间颜色分层：≤3 天红色、≤7 天黄色，其余正常。
- 列表行内直接改状态、一键归档。
- **导出汇总表**：按当前筛选条件一键导出 xlsx（列：序号/标题/单位/类型/城市/发布日期/截止日期/状态/链接/备注），格式对齐常见的"招聘信息汇总表"（参考用户提供样例：金山文档《计算机学院27届招聘信息汇总表》）。

### 6.2 岗位详情

- 正文快照全文、原文链接、全部合并来源；一键"我要投"创建投递记录。

### 6.3 我的投递（看板）

- 待投/已投/笔试/面试/Offer 五列管道视图，点击在列间移动，支持备注（如笔试科目、面试时间）。

### 6.4 源健康页

- 每源上次成功时间、连续失败计数、最近错误信息。

## 7. 提醒机制

- 网页顶栏常驻临期横幅：未来 3 天截止的岗位数量，点击直达已筛好的列表。
- 可选：Windows 桌面 toast 通知，每日早上推送一次临期岗位摘要（默认关闭，设置页可开）。

## 8. 归档规则

- 截止日期过后 7 天，状态自动置为 archived，从默认视图消失；全文搜索仍可召回。

## 9. 错误处理

- 采集失败：重试（指数退避）→ 记日志 → 源健康计数，绝不中断调度循环。
- 字段解析失败（如日期无法解析）：入库但字段留空并标记"需人工核对"，粘贴箱场景由确认页兜底。
- 快照写盘失败：仍入库正文文本，快照路径留空。

## 10. 测试策略

- 适配器单元测试：每个源配真实 HTML fixture，官网改版时测试报警。
- 去重逻辑与中文日期解析（"即日起至3月20日"等）单独测试——历史上最易错点。
- 端到端验收场景：全量采集 → 粘贴公众号链接并确认入库 → 列表筛选 → 创建投递 → 改状态 → 触发归档，全链路走通为完成标准。

## 11. 第一版范围与后续扩展

**MVP 包含**：架构三层全量打通、T1 全部 13 个源（见 source-registry）、三页 + 源健康页、提醒横幅、归档、去重、FTS 搜索、粘贴箱、汇总表 xlsx 导出。

**后续扩展（不在本期）**：RSSHub 接入、Windows 通知默认开启、招聘平台（需评估反爬成本）、简历投递记录导出、多校源。
